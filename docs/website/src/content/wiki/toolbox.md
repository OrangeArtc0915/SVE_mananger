## 工具箱是什么

侧栏「工具箱」收的是**不属于日常流程、但偶尔要用**的东西。列表页一张卡一个工具，点「打开」就在本页内切进去，左上角的「← 返回工具箱」回到列表。

| 工具 | 干什么 | 什么时候用 |
| --- | --- | --- |
| [存档管理](/wiki/saves/) | 看存档摘要、备份、回滚 | 想留个存档备份，或玩崩了要退回去 |
| [环境体检](#环境体检) | 把启动器、游戏目录、SMAPI、Mod、磁盘扫一遍 | 说不清哪里不对，先扫一遍；或者要发求助帖 |
| [Mod 冲突检查](#mod-冲突检查) | 找重复 ID、加载不了、放错层级的 Mod | 装了 Mod 却没生效 |
| [SMAPI 日志分析](#smapi-日志分析) | 读游戏日志，指出是哪个 Mod 在报错 | 游戏报错、闪退、Mod 冲突 |
| [原版文件还原](#原版文件还原) | 把被 Mod 覆盖的游戏原版文件救回来 | 覆盖了游戏文件后游戏出问题，想恢复原版 |

> 这几个工具**只在本机读写你自己的文件**，不联网上传任何东西。「导出反馈包」是你主动点、自己选保存位置才会生成文件。

## 环境体检

一次扫完下面这些，每条给出「正常 / 提示 / 注意 / 问题」四级结论：

- **启动器**：版本、运行时、系统版本；数据目录**能不能写**（放在 Program Files 这类受保护位置时会写不进去，很多怪问题都出在这里）
- **游戏目录**：当前实例指向的目录是否可用、游戏版本是多少
- **SMAPI**：装了没、什么版本
- **Mods 目录**：共几个、启用几个、禁用几个、异常几个
- **依赖关系**：缺失前置、版本过低、循环依赖各有几处
- **版本要求**：有没有 Mod 要求更高的 SMAPI 或游戏版本（装了但拒绝加载，报错只在游戏控制台里，很难自己对上号）
- **Mod 冲突**：重复 ID、加载不了的、放错层级的各有多少
- **磁盘空间**：游戏所在盘与数据所在盘各剩多少（不到 2 GB 会提醒）
- **运行日志**：几份、多大、最近一份是什么时候
- **数据目录占用**：Cache / Log / 存档备份各占多少
- **上次自动更新**：是否有没完成的更新残留

工具条上：

- **复制报告**：把整份结论复制成纯文本，可以直接贴到群里提问
- **导出反馈包**：生成一个 zip，里面是**体检报告 + Mod 清单 + 设置摘要 + 最近 5 份运行日志**。Nexus 密钥与樱花 FRP 密钥**不会**写进包里（设置摘要只记录"有没有配置"，另外所有文本落包前还会把密钥值抹掉）

## Mod 冲突检查

一次性列出三类问题，每条都给出具体目录：

| 类型 | 说明 |
| --- | --- |
| **重复 ID** | 多个**已启用**的 Mod 共用同一个 `UniqueID`。SMAPI 只会加载其中一个，另一个等于白装。留一份禁用着旧版本不算冲突，不会报出来 |
| **加载失败** | `manifest.json` 读不出来，SMAPI 会直接跳过 |
| **不会被加载** | Mods 下的目录里没有 `manifest.json`（压缩包多套了一层、或者装的是要手动覆盖的 XNB 包），以及直接丢在 Mods 根目录下的文件 |

> 这个工具**只看磁盘上已有的信息**，不解析内容包里的 `content.json`。所以「两个美化包抢同一张贴图」这类冲突它查不出来 —— 那种情况要看 [SMAPI 日志分析](#smapi-日志分析) 或者游戏里的实际表现。依赖缺失与版本过低在 [Mod 管理](/wiki/mods/) 与[环境体检](#环境体检)里。

## SMAPI 日志分析

读最近一份 SMAPI 日志，按**来源**（SMAPI 本体、游戏本体、每个 Mod）统计错误与警告，把「谁在刷屏」排在前面 —— 这与 [smapi.io/log](https://smapi.io/log) 的思路一致，只是不用把日志传出去。

日志文件的位置（启动器自己找，取最近改动的那一份）：

```
%APPDATA%\StardewValley\ErrorLogs\SMAPI-crash.txt    上次崩溃时才有
%APPDATA%\StardewValley\ErrorLogs\SMAPI-latest.txt   最近一次运行
```

页面内容：

- **摘要**：日志时间、SMAPI 与游戏版本、共几条错误几条警告
- **按来源**：每个来源一张卡，写着「X 条错误、Y 条警告」并附几条原文（同一条重复刷屏只留一条样例）
- **被跳过的 Mod**：SMAPI 明确写"不再兼容"之类的那些
- **关键错误原文**：去重后的错误行，等宽字体，方便直接对着看
- **复制报告**：把上面全部整理成文本复制出来

> 异常堆栈的续行算作上一条错误的一部分，不会被当成一条条独立错误 —— 否则一个崩溃堆栈就能把某个 Mod 的错误数从几条刷到几十条，排名也就没意义了。

## 原版文件还原

有些 Mod（XNB 替换、Content 覆盖）会**直接覆盖游戏原版文件**。启动器在覆盖前会把原文件复制一份 `.bak-<时间戳>` 留在**同一个目录**里，这个工具就是把这些备份还原回去。

列表里的每一项有两种来源：

| 标记 | 含义 |
| --- | --- |
| **已登记 · 来源** | 这份备份是启动器在某次安装/导入时留下的，索引里记着「是哪个包覆盖的」。**能确定是原版** |
| **未登记** | 索引出现之前留下的 `.bak-` 文件。它可能是原版，也可能是**上一个 Mod 覆盖后的版本** —— 工具不替你下结论，会明确标出来 |

**还原动作**：

1. 先把当前文件另存为 `<文件名>.before-restore-<时间戳>`
2. 再把备份复制回去
3. 备份本身**保留不动**（想再还原一次也行）

所以还原这一步本身也能反悔：真觉得不对，把 `.before-restore-` 那份改回原名就回到还原前了。

> - Mods 目录里的 `.bak-` 不会被列出来 —— 那些是旧版 Mod，不是游戏原版文件
> - 游戏正在运行时还原可能失败（文件被占用），页面会提醒先退出游戏
> - 备份被删掉的条目不再列出（没东西可还原了）
> - 在**设置 → Mod 与下载 → 覆盖前备份**里关掉备份之后，这里就不会有新条目，详见 [设置详解](/wiki/settings/#覆盖前备份)

## 数据存在哪

这几个工具都**不往游戏目录塞多余文件**（除了覆盖前备份本身，它就贴在原文件旁边），其余数据都在启动器数据目录里：

```
Data\save-backups\   存档备份
Data\game-backups\   覆盖前备份的索引（备份文件本身在游戏目录里）
```
