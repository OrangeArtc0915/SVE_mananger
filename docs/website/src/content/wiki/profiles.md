## 什么时候用配置档

同一个 `Mods` 目录里，你可能想要几套完全不同的组合：

- **美化包**：只开画面 / 界面类 Mod，帧数优先
- **剧情包**：大型内容 Mod 配上全套前置
- **性能包**：只留必需品，老机器也能跑

手动一个个勾选太麻烦，也容易点漏。配置档就是把这套「谁开谁关」存下来，以后一键切回去。

## 保存与应用

入口在「Mod 管理」页工具栏的「配置档」按钮，打开的是「Mod 配置档」窗口：

| 按钮 | 作用 |
| --- | --- |
| 保存当前状态 | 把当前 Mod 目录的启停状态存成一份新档，可以起个名字 |
| 应用 | 把选中的档套到当前 Mod 列表上 |
| 用当前状态覆盖 | 用当前状态更新选中的档，原来的记录找不回来 |
| 重命名 | 改这份档的名字 |
| 导出 | 另存为一份 json |
| 导入配置档… | 从 json 导入一份档 |
| 删除 | 删掉这份记录，Mod 文件不受影响 |

窗口只列出**当前 `Mods` 目录**下的档，换实例后看到的是那个目录对应的档。

点「应用」时会先弹确认，里面写明「文件名只会加 / 去开头的点，不会删改任何 Mod 文件」。

> 如果游戏正在运行，应用完之后请**重开游戏**才会生效。

## 配置档里存的是什么

- 只存**启停状态**，不存 Mod 文件，也不存版本
- 每条记录按 Mod 的 **UniqueId** 对应；Mod 没有 UniqueId 时，用**去掉点前缀的文件夹名**对应 —— 所以一个 Mod 被禁用（目录名加了点）之后依然能对上，不会错乱
- 还会记下这份档对应的 `Mods` 目录，用来判断该在哪个实例下显示

「启用 / 禁用」本身做的就是把 Mod 文件夹改名（启用去掉开头的 `.`，禁用在前面补一个 `.`），配置档复用的就是同一套动作。

**同名目录冲突会导致这一条失败**：比如要把 `ABC` 改成 `.ABC`，但 `.ABC` 已经存在，那条会报「目标目录已存在」。这类失败会逐条收集并列出来，其余能改的照常应用，不会因为一条失败就整份档中止。档里记着、但当前目录里已经没有的 Mod，会单独列成「不在 Mods 目录里的」。

## 和「标签」的区别

| | 标签 | 配置档 |
| --- | --- | --- |
| 存什么 | 你贴的分类标记 | 成套的启停方案 |
| 用途 | 列表筛选，快速找 Mod | 一键切换整组启停 |
| 会不会动 Mod | 不会 | 会改 Mod 文件夹名（只加 / 去点） |

简单说：标签是「看得见的分组」，配置档是「真的按下去」的启停组合。

## 拖拽安装

不用先点进 Mod 管理页：把文件**拖到启动器窗口任意位置**就行。

支持的拖入内容：

- 压缩包：`zip` / `rar` / `7z` / `tar` / `gz`
- 一个 Mod 文件夹（直接拖目录）

松手后启动器会自动切到「Mod 管理」页并开始导入：`Mod 管理` 页会识别包结构、按识别的结果安装，装完弹一份汇总（成功 / 失败各几个、装入了几个 Mod，有警告或错误也会列出来），页面列表随之刷新。

一次拖多个也行：能识别的照常处理，不能识别的会明确告诉你「都不是能识别的 Mod 包」。页面上点「导入 Mod」可以手动选文件，这个入口同样支持**多选**。

## 有哪些限制

- **原版实例不加载 Mod**：配置档只对 Mod 端（走 SMAPI）的实例有意义
- **导出 / 导入的是启停组合，不含 Mod 本身**：换机器时先装好 Mod，再导入配置档
- 应用后会重扫一遍 Mod 列表；游戏正在运行时，要重开游戏才生效
- 配置档存在 `Data\profiles\`，一档一个 json 文件，可以直接手工编辑或拷给别人
