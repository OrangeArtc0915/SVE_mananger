## 三种装 Mod 的方式

### 1. 导入压缩包

把 `zip` / `rar` / `7z` / `tar` / `gz` 拖进「Mod 管理」页，或者点「导入」选择文件。启动器会先看压缩包结构，判断这是「放进 Mods 目录的普通 Mod」还是「需要覆盖游戏文件的包」。

### 2. 在线下载

到「资源中心 → 在线浏览」，在内嵌浏览器里打开 Mod 站点：

- 在 Nexus 页面上点 **「Mod Manager Download」** 即可交给启动器下载（**非会员也能用**）
- 想让浏览器里的下载按钮直接唤起启动器，可以在设置里开启 `nxm://` 协议关联
- 在设置里开启「监控下载目录」后，你用浏览器下载的 Mod 压缩包会被自动发现并入库

> 启动器**不再保存** Nexus 个人密钥：能匿名访问的接口照常可用，需要鉴权的会直接给出可读的失败原因；通过页面上的「Mod Manager Download」（nxm 链接）唤起下载不受影响，非会员也能用。

### 3. 从 Mod 库补齐

缺前置时，直接从本地 Mod 库一键补齐，不用重新下载。

## 启用与停用

每个 Mod 可以单独启用 / 停用，停用后 SMAPI 启动时不会加载它 —— 排查问题时这是最快的验证手段：全停掉再一个个开。

删除有两条路：直接从列表删除，或移入回收站（受设置里「删除到回收站」控制，默认开启，误删可救）。

## 安装规划：动手前先看清楚

Content 覆盖、XNB 替换、Reshade 这类**非标准包**，启动器会先列出一份计划：

- 会覆盖哪些文件
- 会替换哪些 XNB
- 会装到哪个目录

确认之后才动手。覆盖前会**自动备份**（受「导入前自动备份」控制，默认开启），装错了可以退回来。

## 依赖检查

启动器会递归解析每个 Mod 的 `manifest.json`，把前置关系展开：

- 谁缺前置、缺哪一个，列表里一目了然
- 缺的可以从 Mod 库补齐，或去对应站点下载

## 中文名与搜索

启动器会从 Mod **自己的文件**里找中文名：

| 从哪找 | 说明 |
| --- | --- |
| `manifest.json` 的 `Name` | 本身就写了中文的，直接用 |
| Mod 文件夹名 | 文件夹是中文的（很多人手动改过） |
| `i18n` 里的中文翻译 | `zh.json` / `zh-CN.json` / `zh-Hans.json` / `zh-Hant.json` / `zh-TW.json` 里的 `name` / `modname` 等键 |

认出来的中文名直接显示在卡片上，旁边标一个「中文名」的小胶囊 —— 鼠标停上去能看到原名。**搜索时中英文都能用**。只读 Mod 自己的文件：不联网、不改 Mod、不往 manifest 里写东西。

## 检查更新

开启「检查 Mod 更新」（默认开启）后，启动器会比对每个 Mod 的版本，有新版本的在列表里标一个可点的标记，点它就打开新版本的下载页。

它走的是 [smapi.io](https://smapi.io) 的公开接口（**不需要任何密钥**），依据是每个 Mod 的 `manifest.json` 里的 `UpdateKeys`：

- **只有写了 `UpdateKeys` 的 Mod 才查得到** —— manifest 里没写，启动器就无从知道该去哪个站点比对
- 进 Mod 管理页会自动查一次，结果缓存 6 小时，不会反复去问对方接口；想立刻重查就点工具栏的「检查更新」
- 查不到也不影响使用：连不上时会退回显示上次的结果，并在提示条里说明

## 一键更新

工具栏「一键更新」把**能自动装**的更新直接装掉，不用自己再去网页下载：

- 先弹确认框，列出这次会更新哪些 Mod、哪些需要你手动处理
- 能自动装的是 `UpdateKeys` 里写了 `GitHub:owner/repo` 的那些：启动器取该仓库最新 release 里的 `.zip`，下载、解压、装进当前实例
- **旧版本目录会先备份**；原来是停用的 Mod，更新后仍是停用
- 装完自动重扫，列表里的版本号跟着变

更新来源不是 GitHub 的（例如 Nexus）不会自动装，只会在确认框里列出来提醒你手动处理。

> 只自动装 GitHub 官方 release 里的包，不抓第三方聚合站，也不做任何鉴权绕过。

## 自动修复

工具栏「自动修复」先扫一遍，把**能确定修法**的问题列出来让你确认，确认后一次性修完：

| 问题 | 怎么修 |
| --- | --- |
| `manifest.json` 语法坏 | 清掉 BOM、注释、多余的尾逗号，重写成合法 JSON；缺 `UniqueID` 的补一个新的 |
| 目录多套了一层 | 把里层真正的 Mod 提上来，外层空壳删掉 |
| 重复 `UniqueID` | 保留第一个启用的，其余的自动停用（目录名加 `.` 前缀），**不删文件** |

改 `manifest.json` 之前会先存一份 `manifest.json.bak-<时间戳>`；修完会自己再读一遍验证，读不出来就当作没改。拿不准的问题（例如 JSON 已经被截断）会明确说明「超出自动修复范围」，原样不动。

## Mod 合集

「Mod 合集」是配置档的一个更轻的用法：把**当前启用着的那一套**直接抓成一份快照。

1. 把这一套调好，在上面填个名字（备注可留空），点「保存当前启用为合集」
2. 想切回来时，对着那份合集点「套用」——启动器会先列出**将要发生什么**（要启用哪些、要禁用哪些、合集里有几个在磁盘上找不到），确认后才动手
3. 套用只改 Mod 目录名的点前缀，**不删除也不修改任何 Mod 文件**，随时能套用别的合集切回去

合集存在 `Data\mod-collections.json`，记的是 Mod 的标识而不是文件夹名，所以禁用改名后照样能对上。

> 套用合集会**主动关掉不在合集里的 Mod**。如果只想启用几个、不动其他，用列表上的启用按钮更合适。

## Mod 翻译

「Mod 翻译」可以调翻译服务把 Mod 的名称与描述翻成中文，结果按 Mod 的标识存在 `Data\mod-translations.json`。

服务商与密钥在[设置 → 网络与账号 → Mod 翻译](/wiki/settings/#mod-翻译)里配，支持微软翻译（默认）、百度翻译、DeepL；请求结果另有缓存（`Data\translate-cache.json`，默认一周过期）。

## Mod 库

Mod 库是「已下载 / 已解压、还没装进某个实例」的 Mod 集合，可以理解为你的私人仓库。它的位置可以在设置里改（Mod 很多时建议放到空间大的盘）。

下载完成后是否自动解压入库、是否顺带装进当前实例，分别由两个开关控制（前者默认开，后者默认关）。

## 下载慢怎么办

启动器内下载支持**多连接分片**与**断点续传**：服务器支持时最多 6 个连接同时下，中断后从各自断点接着下。但速度上限仍取决于你的网络与站点线路 —— 启动器不缓存也不加速。

实在慢可以先用浏览器下好，再用「导入」放进 Mod 库，效果一样。
