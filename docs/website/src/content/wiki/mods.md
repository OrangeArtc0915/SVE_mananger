## 三种装 Mod 的方式

### 1. 导入压缩包

把 `zip` / `rar` / `7z` / `tar` / `gz` 拖进「Mod 管理」页，或者点「导入」选择文件。启动器会先看压缩包结构，判断这是「放进 Mods 目录的普通 Mod」还是「需要覆盖游戏文件的包」。

### 2. 在线下载

到「资源中心 → 在线浏览」，在内嵌浏览器里打开 Mod 站点：

- 在 Nexus 页面上点 **「Mod Manager Download」** 即可交给启动器下载（**非会员也能用**）
- 想让浏览器里的下载按钮直接唤起启动器，可以在设置里开启 `nxm://` 协议关联
- 在设置里开启「监控下载目录」后，你用浏览器下载的 Mod 压缩包会被自动发现并入库

> 查询 Mod 详情与在线下载需要一个 Nexus 个人 API 密钥（可选）；**检查更新不需要密钥**，走的是公开接口。

### 3. 从 Mod 库补齐

缺前置时，直接从本地 Mod 库一键补齐，不用重新下载。

## 启用与停用

每个 Mod 可以单独启用 / 停用，停用后 SMAPI 启动时不会加载它 —— 排查问题时这是最快的验证手段：全停掉再一个个开。

删除有两条路：直接从列表删除，或移入回收站（受设置里「删除到回收站」控制，默认开启，误删可救）。

## 安装规划：动手前先看清楚

Content 覆盖、XNB 替换、Reshade 这类**非标准包**，启动器会先列出一份计划：

- 会覆盖哪些文件
- 会替换哪些 XNB
- 会装到哪个目录

确认之后才动手。覆盖前会**自动备份**（受「导入前自动备份」控制，默认开启），装错了可以退回来。

## 依赖检查

启动器会递归解析每个 Mod 的 `manifest.json`，把前置关系展开：

- 谁缺前置、缺哪一个，列表里一目了然
- 缺的可以从 Mod 库补齐，或去对应站点下载

## 检查更新

开启「检查 Mod 更新」（默认开启）后，启动器会比对每个 Mod 的版本，有新版本的在列表里标一个可点的标记，点它就打开新版本的下载页。

它走的是 [smapi.io](https://smapi.io) 的公开接口（**不需要 Nexus API 密钥**），依据是每个 Mod 的 `manifest.json` 里的 `UpdateKeys`：

- **只有写了 `UpdateKeys` 的 Mod 才查得到** —— manifest 里没写，启动器就无从知道该去哪个站点比对
- 进 Mod 管理页会自动查一次，结果缓存 6 小时，不会反复去问对方接口；想立刻重查就点工具栏的「检查更新」
- 查不到也不影响使用：连不上时会退回显示上次的结果，并在提示条里说明

## Mod 库

Mod 库是「已下载 / 已解压、还没装进某个实例」的 Mod 集合，可以理解为你的私人仓库。它的位置可以在设置里改（Mod 很多时建议放到空间大的盘）。

下载完成后是否自动解压入库、是否顺带装进当前实例，分别由两个开关控制（前者默认开，后者默认关）。

## 下载慢怎么办

启动器内下载支持**多连接分片**与**断点续传**：服务器支持时最多 6 个连接同时下，中断后从各自断点接着下。但速度上限仍取决于你的网络与站点线路 —— 启动器不缓存也不加速。

实在慢可以先用浏览器下好，再用「导入」放进 Mod 库，效果一样。
