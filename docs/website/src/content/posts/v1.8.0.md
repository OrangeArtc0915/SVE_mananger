## 这一版做了什么

这一版把「装好 Mod 之后」最烦的三件事补上了：**认不出中文名、一个个手动更新、装错了看不出错在哪**。

### 中文名自动识别

以前列表里全是英文名，或者干脆显示文件夹名，一堆 Mod 排在旁边对不上号。现在启动器会从 Mod **自己的文件**里把中文名找出来：

| 从哪找 | 说明 |
| --- | --- |
| `manifest.json` 的 `Name` | 本身就写了中文的，直接用 |
| Mod 文件夹名 | 文件夹是中文的（很多人手动改过） |
| `i18n` 里的中文翻译 | 找 `zh.json` / `zh-CN.json` / `zh-Hans.json` / `zh-Hant.json` / `zh-TW.json` 里的 `name` / `modname` 等键 |

认出来的中文名直接显示在卡片上，旁边还标一个「中文名」的小胶囊 —— 鼠标停上去能看到原名，不会让你忘了这是哪个 Mod。

> **搜索中英文都能用**：记得中文名就搜中文，记得原名就搜英文，两边都能搜到。

> 只读 Mod 自己的文件：不联网、不改 Mod、不往 manifest 里写东西。

### 一键更新

「检查更新」上一版就有了，但查到新版本之后还得自己去网页下载、解压、替换。这一版把这条链路走完：

- Mod 管理页工具栏「检查更新」旁边多了「**一键更新**」，先弹确认框列出将要更新的 Mod，确认后一次性装掉
- 能自动装的是 `manifest.json` 里 `UpdateKeys` 写了 `GitHub:owner/repo` 的那些：启动器去取该仓库的最新 release，挑里面的 `.zip` 下载、解压、装进当前实例
- **旧版本目录会先备份**，装错了还能拿回来
- 原来是**停用**状态的 Mod，更新之后仍然是停用的，不会被悄悄打开
- 装完自动重扫，列表里的版本号跟着变

**哪些装不了**：更新来源不是 GitHub 的（例如 Nexus），确认框里会把它们单独列出来，告诉你需要手动处理 —— 启动器不替你猜。

> 只自动装 GitHub 官方 release 里的包，不抓第三方聚合站，也不做任何鉴权绕过。

### 自动修复

「Mod 冲突检查」能看出毛病，但看出来之后往往还要自己去改文件。这一版对**三类能确定修法**的问题直接动手：

| 问题 | 怎么修 |
| --- | --- |
| **`manifest.json` 语法坏** | 清掉 BOM、注释、多余的尾逗号这类不合法写法，重写成合法 JSON；缺 `UniqueID` 的补一个新的 |
| **目录多套了一层** | 把里层真正的 Mod 提上来，外层空壳删掉 |
| **重复 UniqueID** | 保留第一个启用的，其余的自动停用（目录名加 `.` 前缀），**不删文件** |

几个安心的细节：

- 改 `manifest.json` 之前，原文先存一份 `manifest.json.bak-<时间戳>`
- 修完会自己再读一遍验证；读不出来就**当作没改**，宁可不写
- 拿不准的（例如 JSON 已经被截断）会明确告诉你「超出自动修复范围」，原样不动

### 设置页也能做这三件事

「设置 → Mod 与下载」这张卡下面多了一段 **Mod 维护**，放的就是 检查更新 / 一键更新 / 自动修复 这三个按钮，底下有一行状态文字显示进度与结果。

它和「Mod 管理」页**读写同一份扫描结果**：在设置里检查完更新，切回 Mod 管理页就是查好的状态；在 Mod 管理页一键更新完，再回设置页也不会重扫一遍。

### 密钥相关

- **不再保存 Nexus 个人密钥**：设置页里的密钥输入框已经去掉，在线浏览窗口里的「已配置 Key / 未配置 Key」提示也一并删掉。需要鉴权的接口会直接返回可读的失败原因；`nxm://` 唤起下载这条路不受影响，非会员照常可用
- **密钥加密落盘**：樱花 FRP 访问密钥这类设置改用 Windows DPAPI 加密后再写进 `Settings.json`（只有当前 Windows 账户能解开）。以前明文存的，启动时会自动转成密文
- 导出反馈包里不再有 Nexus 密钥这条记录；樱花 FRP 密钥的值在落包前仍会被抹掉
