# 发行与下载页说明

这份文档说明：发行版本号从哪来、本地怎么产出发行包、下载页在哪、以及怎么把一版发出去。

---

## 一、当前发行版本

| 项 | 值 |
| --- | --- |
| 版本号 | **v1.0.0** |
| 版本号唯一来源 | `src/StardewLauncher.Core/App/AppInfo.cs` 里的 `Version` 常量 |
| 目标平台 | Windows 10 1809 及以上 / Windows 11，x64 |
| 运行时 | 自包含 .NET 8，用户无需另装 |

> 但 `README.md` 与 `docs/website/index.html` 里出现的 `v1.0.0` 是写死的文案，记得同步。

## 二、本地发行包怎么产出、在哪

双击仓库根目录的 **`build.bat`**，产出：

```
publish\StardewLauncher.exe                     单文件 exe，自带运行时，直接双击可跑
publish\StardewLauncher-v1.0.0-win-x64.zip      发给用户的发行压缩包
publish\Data\                                   运行时数据（设置/实例/日志），build.bat 不会动它
```

zip 内部结构：

```
StardewLauncher.exe
README.md
NOTICE
LICENSE
```

## 四、怎么发一版

### 方式 A：命令行（推荐，可直接复制）

```powershell
cd f:\SVE\Tool
.\build.bat

gh release create v1.0.0 "publish\StardewLauncher-v1.0.0-win-x64.zip" `
  --title "星露谷启动器 v1.0.0" `
  --notes "首个公开版本：实例管理、Mod 管理（zip / rar / 7z）、安装计划、依赖检查与一键补齐、内置八个 Mod 站点下载、现实天气与月历、一键安装 SMAPI。"
```

要点：

- 资产文件名保持 `StardewLauncher-v1.0.0-win-x64.zip` 这个格式 —— README 与官网都按这个命名写的
- tag 用 `v1.0.0`（带 v 前缀），与 AppInfo 里的 `Version`（不带 v）区分开
- 想直接发成正式版就别加 `--draft`；想先预览加 `--draft`，之后在网页上点 Publish

### 方式 B：网页操作

1. 打开 <https://github.com/OrangeArtc0915/SVE_mananger/releases/new>
2. **Choose a tag** 填 `v1.0.0`，target 选 `main`
3. 填标题与说明
4. 把 `publish\StardewLauncher-v1.0.0-win-x64.zip` 拖进附件区
5. 点 **Publish release**

### Gitee 备用渠道

Gitee 文件库（<https://gitee.com/orangearc655743/SVE_mananger_File>）没有 Releases 概念，直接把同一个 zip 传到仓库里即可；建议放在 `release/` 目录下，与 `resource/`（SMAPI 镜像）分开。

## 五、发布后要顺手确认的

- [ ] Releases 页面能看到 `StardewLauncher-v1.0.0-win-x64.zip` 附件
- [ ] 官网「下载最新版」按钮能跳到 Releases 页
- [ ] 仓库 About 的 Website 字段填官网地址（Settings 里改，或 `gh api` 设置）
- [ ] 官网 Pages 构建状态是 `built`：`gh api repos/OrangeArtc0915/SVE_mananger/pages --jq .status`

## 六、本地自检清单

发版前跑一遍：

- [ ] `publish\StardewLauncher.exe` 的「文件版本」等于当前版本号（右键属性 → 详细信息）
- [ ] zip 内确实有 4 个文件（exe / README.md / NOTICE / LICENSE）
- [ ] exe 能在干净目录下双击启动，并自动生成 `Data\`
- [ ] `dotnet build StardewLauncher.sln -c Release` 为 0 错误 0 警告
