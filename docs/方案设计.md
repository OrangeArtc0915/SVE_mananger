### 1.1 SMAPI 的命令行与配置

来源：[SMAPI docs/technical/smapi.md](https://github.com/Pathoschild/SMAPI/blob/3.5/docs/technical/smapi.md)、[deepwiki: Mod Discovery](https://deepwiki.com/Pathoschild/SMAPI/3.1-mod-discovery-and-validation)、[deepwiki: Configuration System](https://deepwiki.com/Pathoschild/SMAPI/2.6-configuration-system)

| 事实 | 内容 | 风险 |
|---|---|---|
| 安装器参数 | `--install`、`--uninstall`、`--game-path "path"` 可跳过交互 | 官方支持 |
| `--mods-path` | 存在，但官方原文：*"intended for internal use or testing and may change without warning"* | ⚠️ 未公开接口 |
| 环境变量 | `SMAPI_MODS_PATH`、`SMAPI_NO_TERMINAL` 等价于上面两个参数 | 官方文档只在 Linux/Mac 场景说明；**Windows 是否稳定生效待实测** |
| **禁用机制** | 扫描 `Mods` 时，**文件夹名以 `.` 开头 → 直接标记 `ModType.Ignored`** | ✅ 官方原生机制，非黑魔法 |
| 无 manifest | 目录没有 `manifest.json` → 跳过（不是错误） | 官方行为 |
| **加载顺序** | `smapi-internal/config.json` 的 `ModsToLoadEarly` / `ModsToLoadLate` 数组控制；**同一数组内的顺序即相对顺序**；在依赖解析之前应用 | 官方支持 |
| 配置分层 | ① `smapi-internal/config.json`（基础，**SMAPI 升级时被重置**）② `smapi-internal/config.user.json`（用户覆盖，**升级保留**）③ `<mods目录>/SMAPI-config.json`（按 Mods 目录覆盖） | ✅ 官方三层 |
| 每目录配置 | 使用自定义 mods 目录时，可在该目录放 `SMAPI-config.json`，实现"不同 Mod 配置方案用不同设置" | ⚠️ 能否在其中覆盖 `ModsToLoadEarly/Late` **待实测** |

### 1.2 星露谷的路径与 Mod 格式

来源：[Stardew Wiki: Getting Started](https://stardewvalleywiki.com/Modding:Player_Guide/Getting_Started)、[Saves](https://stardewvalleywiki.com/Saves)、[Manifest](https://stardewvalleywiki.com/Modding:Modder_Guide/APIs/Manifest)

- 游戏目录（默认）：
  - Steam：`C:\Program Files (x86)\Steam\steamapps\common\Stardew Valley`
  - GOG：`C:\Program Files (x86)\GOG Galaxy\Games\Stardew Valley` 或 `C:\GOG Games\Stardew Valley`
  - Xbox：`C:\XboxGames\Stardew Valley`
- 游戏 exe 可能是 `Stardew Valley.exe` **或** `StardewValley.exe`（两种都要认）
- 存档：`%appdata%\StardewValley\Saves`
- SMAPI 日志：`%appdata%\StardewValley\ErrorLogs`
- **SMAPI 安装完成的标志**：游戏目录存在 `StardewModdingAPI.exe` + `smapi-internal\` + `Mods\`
- Mod 安装方式：解压后**整个 mod 文件夹**放到 `Mods\` 下（必须是独立子目录，不要在 mod 文件夹外层多包一层）
- `manifest.json` 字段：

| 字段 | 必需 | 说明 |
|---|---|---|
| `Name` / `Author` / `Version` / `Description` / `UniqueID` | ✅ | `Version` 为语义化版本；`UniqueID` 是依赖与更新的主键 |
| `EntryDll` **或** `ContentPackFor` | ✅ | 二者互斥：前者是代码 Mod，后者是内容包（内容是 `{UniqueID, MinimumVersion}`） |
| `MinimumApiVersion` / `MinimumGameVersion` | ❌ | 最低 SMAPI / 游戏版本 |
| `Dependencies[]` | ❌ | `{UniqueID, MinimumVersion?, IsRequired?}`，`IsRequired` 缺省为 `true` |
| `UpdateKeys[]` | ❌ | 更新检查用，如 `Nexus:1915`、`GitHub:owner/repo` |

### 1.3 更新检查接口

来源：[SMAPI docs/technical/web.md](https://github.com/Pathoschild/SMAPI/blob/develop/docs/technical/web.md)

- **Mod 更新**：`POST https://smapi.io/api/{version}/mods` —— **公开、无需 Nexus API Key**，会交叉引用 Nexus / CurseForge / ModDrop / 官方 Wiki，直接返回 `suggestedUpdate`
  - 请求体：`{ mods: [{ id, updateKeys, installedVersion, isBroken }], apiVersion, gameVersion, platform, includeExtendedMetadata }`
  - `includeExtendedMetadata: true` 时额外返回 `metadata`，含 `compatibilityStatus`（兼容性状态）、`nexusID`、`brokeIn` 等
  - ⚠️ 官方原文：*"publicly accessible but not officially released; it may change at any time"*
- **SMAPI 自身更新**：`GET https://api.github.com/repos/Pathoschild/SMAPI/releases/latest`
  - ⚠️ **未鉴权时限制 60 次/小时**。本次调研中已实际撞到该限制。→ 必须做本地缓存 + 仅手动/低频触发

## 2. 三个关键架构决策

### 决策一：Mods 隔离 —— 不采用 PCL 的"切换工作目录"

PCL 的"版本隔离"**不建任何链接，也不复制文件**，只是改变游戏进程的 Working Directory（`ModLaunch.cs:2496`）。这个技巧对 Minecraft 有效，因为 MC 的 `mods\`、`saves\` 都相对游戏根目录定位。

**但星露谷不成立**：SMAPI 从游戏目录找 `Mods`，存档写死在 `%appdata%\StardewValley\Saves`，二者不在同一棵树。

因此本方案采用两套可实现、可切换的隔离方式：

| 模式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 直挂模式（默认）** | 把 `<游戏目录>\Mods` 做成 junction → `<实例>\Mods` | 对 SMAPI 完全透明，不依赖任何未公开接口 | 会改动游戏目录；切换实例时需重建链接 |
| **B. 重定向模式** | 不碰游戏目录，用 `SMAPI_MODS_PATH` 环境变量把 SMAPI 指向 `<实例>\Selected Mods`，其中每个启用的 Mod 各建一个 junction | 完全不污染游戏目录 | 依赖环境变量（Windows 下稳定性待实测） |

- junction 用 `mklink /J` 实现：**不需要管理员权限、不需要开发者模式**（这是 Windows 上目录链接相对符号链接的关键优势）。Stardrop 生产环境即用此法（`MainWindow.axaml.cs:3454`）。
- 切换实例时采用**幂等重建**：先删链接目录下所有子项，再全量重建。逻辑简单且能自愈（Stardrop 同做法）。
- 长路径（>260 字符）需加 `\\?\` 前缀。

### 决策二：单个 Mod 启停 —— 用官方 `.` 前缀机制

不走 PCL 的 `.disabled` 后缀（那是 Forge/Fabric 的约定，SMAPI 不认识），而用 **SMAPI 原生的"文件夹名以 `.` 开头即忽略"**：

```
Stardew Valley Expanded      →  .Stardew Valley Expanded     （禁用）
.Stardew Valley Expanded     →  Stardew Valley Expanded      （启用）
```

零风险、完全可逆、不移动文件、SMAPI 官方支持。

### 决策三：加载顺序 —— 写官方配置，不改文件夹名

社区通行做法是给文件夹名加 `z` 前缀来影响字母序加载，**我们不这么做**，改为写 SMAPI 官方支持的加载顺序覆盖：

- 默认写入 `<实例>\Mods\SMAPI-config.json`
  - 该文件属于官方三层配置的"每 Mods 目录"层，**天然 per-实例**
  - SMAPI 升级不会重置它（不同于 `smapi-internal/config.json`）
  - ⚠️ **待实测**：该文件能否覆盖 `ModsToLoadEarly` / `ModsToLoadLate`
- 若实测不支持，回退方案：写 `smapi-internal/config.user.json`（升级保留，但全局，多实例会互相覆盖）

依赖检查（缺依赖 / 版本不符 / 循环依赖）由本工具自己做，结果只用于**报警与排序建议**，实际加载顺序仍由 SMAPI 自己解析依赖——避免与 SMAPI 的判断打架。

## 3. 数据模型

### 3.1 实例（Instance）

一个"游戏配置方案"，是工具的核心实体。

```jsonc
{
  "id": "8f3a1c...",                 // GUID，稳定身份，不用名称做主键
  "name": "SVE 整合包",               // 显示名，允许重名（用 id 区分）
  "note": "带 SVE + 美化",
  "gameDir": "C:\\...\\Stardew Valley",  // 指向游戏本体
  "isolationMode": "Junction",        // Junction | SmapiModsPath
  "modsDir": "<数据目录>\\instances\\8f3a1c...\\Mods",   // Mod 实体文件存放处
  "isolateSaves": false,             // 存档隔离开关，默认关
  "savesDir": "<数据目录>\\instances\\8f3a1c...\\Saves",
  "sortMode": "Dependency",          // 排序方式
  "enabledMods": [                    // 启用清单 + 顺序（也用于禁用项记录）
    { "uniqueId": "Pathoschild.ContentPatcher", "enabled": true, "order": 10 },
    { "uniqueId": "FlashShifter.StardewValleyExpandedCP", "enabled": true, "order": 30 }
  ],
  "customIcon": "icon.png",
  "createdAt": "2026-09-12T10:00:00Z",
  "lastLaunchAt": "2026-09-12T20:15:00Z",
  "totalPlaySeconds": 36120,
  "hidden": false
}
```

**存储**：每实例一个 JSON 文件，放 `<数据目录>\instances\<id>.json`。
**为什么不用"实例 = 目录名"（PCL 的做法）**：星露谷实例不一定有独立目录（重定向模式下 Mod 是独立目录、游戏本体是共享的），用 GUID + 独立描述文件更贴合真实结构，也允许重名与重命名。

### 3.2 Mod 条目（ModEntry）

由扫描 Mods 目录现场生成，不持久化（可缓存）。

```jsonc
{
  "folderName": ".Stardew Valley Expanded",     // 实际文件夹名
  "rawFolderName": "Stardew Valley Expanded",   // 剥离 "." 前缀后的名字
  "folderPath": "...\\Mods\\.Stardew Valley Expanded",
  "state": "Enabled",                            // Enabled | Disabled | Invalid
  "manifest": {
    "name": "Stardew Valley Expanded",
    "author": "FlashShifter",
    "version": "1.15.0",
    "description": "...",
    "uniqueId": "FlashShifter.StardewValleyExpandedCP",
    "entryDll": null,
    "contentPackFor": { "uniqueId": "Pathoschild.ContentPatcher", "minimumVersion": "2.0.0" },
    "minimumApiVersion": "3.18.0",
    "minimumGameVersion": null,
    "dependencies": [ { "uniqueId": "...", "minimumVersion": "1.0.0", "isRequired": true } ],
    "updateKeys": [ "Nexus:3753" ]
  },
  "parseError": null,                 // 非 null 表示 Invalid 及原因
  "suggestedUpdate": null,            // 联网检查后填充
  "compatibilityStatus": null         // 来自 smapi.io 的兼容性状态
}
```

### 3.3 全局设置（Settings）

```jsonc
{
  "version": 1,                       // 配置版本号，用于将来迁移
  "gameDir": "",                      // 最近使用的游戏目录
  "language": "zh-CN",
  "theme": "Light",                   // Light | Dark | System
  "colorTheme": "SkyBlue",
  "modsDirDefault": "",               // 新实例 Mod 库的默认根
  "backupBeforeImport": true,
  "deleteToRecycleBin": true,
  "isolateSavesByDefault": false,
  "gitHubUpdateCheckEnabled": true,
  "modUpdateCheckEnabled": true,
  "checkUpdateOnStartup": false,      // 默认关，避免撞 API 限流
  "lastSelectedInstanceId": ""
}
```

**存储**：`<数据目录>\Settings.json`（`System.Text.Json`，缩进写出，`AllowTrailingCommas`）。

## 4. 目录结构

### 4.1 工具自身的数据目录

参照 PCL 的四类目录划分（`PCL.Core\App\Paths.cs:64-91`），但去掉「跨用户共享」这类对单机工具无意义的划分：

```
<工具目录>\Data\            程序私有数据（随程序走，便于便携部署）
  ├─ Settings.json
  ├─ instances\<id>.json    实例描述
  ├─ instances\<id>\Mods    实例 Mod 库（实体文件）
  ├─ instances\<id>\Saves   实例存档（开启隔离时）
  ├─ Cache\                 可重建的缓存（Mod 扫描结果、版本检查结果）
  └─ Log\                   工具自身日志

%LOCALAPPDATA%\StardewLauncher\Downloads\     Mod 导入的临时解压目录（可随时删）
%TEMP%\StardewLauncher\                       解压中间物
```

> 支持环境变量 `STARDEWLAUNCHER_DATA` 覆盖数据目录（便于测试与便携部署）。

### 4.2 与游戏目录的关系

```
模式 A（直挂）：
  <游戏目录>\Mods                      → junction → <数据目录>\instances\<id>\Mods

模式 B（重定向）：
  <游戏目录>\Mods                       → 保持不动（可完全不用）
  <数据目录>\instances\<id>\Selected Mods\<Mod名>  → junction → Mod 实体目录
  启动时设 SMAPI_MODS_PATH = <数据目录>\instances\<id>\Selected Mods
```

### 5.1 分层原则

- **Core 完全不引用 WPF**，所有文件/进程/网络操作都在 Core，UI 只做展示与交互。这样 Core 可单元测试，也便于将来换 UI 框架。
- **UI 用 MVVM**（`CommunityToolkit.Mvvm`），不用 PCL 的 code-behind + 全局静态服务定位器。
  > 这是**有意偏离 PCL**：PCL 的 `PageInstanceCompResource.xaml.cs` 是 2000+ 行的上帝类，UI 与业务严重耦合，列表用 `StackPanel.Children` 手工维护。我们只借鉴它的**视觉与布局**，架构上用 MVVM + `ObservableCollection`。这一点需要你确认（见第 9 节）。

## 7. 关键技术实现要点

### 7.1 游戏目录探测（我们自己实现）

按优先级依次尝试，命中即止：

1. 设置里已保存的路径（校验有效性）
2. **Steam**：解析 `libraryfolders.vdf` 找所有库目录 → 逐个检查 `<库>\steamapps\common\Stardew Valley`
   - 默认位置：`C:\Program Files (x86)\Steam\steamapps\libraryfolders.vdf`
   - 同时读注册表 `HKCU\Software\Valve\Steam\SteamPath` 找 Steam 安装位置
   - VDF 是 KeyValues 格式，手写轻量解析器（约 100 行，无需第三方库）
3. **GOG**：注册表 `HKLM\SOFTWARE\WOW6432Node\GOG.com\Games\*` 下的 `path` 值
4. **Xbox**：`C:\XboxGames\Stardew Valley`
5. 以上都失败 → 弹目录选择框让用户手动指定

**有效性校验**：目录下存在 `Stardew Valley.exe` **或** `StardewValley.exe`（两种都要认）。

### 7.2 SMAPI 检测与安装

**检测**：游戏目录存在 `StardewModdingAPI.exe` + `smapi-internal\` → 已安装。
**版本读取**：读 `StardewModdingAPI.dll` 的程序集版本（Stardrop 做法，Windows 上也读 dll）。

**安装流程**（参照 Stardrop 已验证的做法）：

1. 检查游戏进程是否在运行 → 在运行则拒绝并提示
2. `GET https://api.github.com/repos/Pathoschild/SMAPI/releases/latest` 取 `tag_name`
3. 拼下载地址 `https://github.com/Pathoschild/SMAPI/releases/download/{tag}/SMAPI-{tag}-installer.zip`
4. 流式下载并解压到临时目录（带进度回调）
5. 解压 `<临时>\internal\windows\install.dat` 到游戏目录（覆盖）
6. 若游戏目录存在 `Stardew Valley.deps.json` → 复制为 `StardewModdingAPI.deps.json`
7. 清理临时目录
8. 校验安装结果

> **备选方案**：调用官方安装器 `SMAPI.Installer.exe --install --game-path "..."`。官方参数是公开接口、更不易随版本失效，但需处理控制台交互，第一版先不上。

**权限问题**：Steam 默认目录在 `C:\Program Files (x86)` 下，写入需要管理员权限。→ 启动时**不**强制要求管理员；仅在需要写入受保护目录时检测并给出明确指引（提示以管理员身份重启）。

### 7.3 实例切换 / 隔离实施

**模式 A（直挂）启用某实例**：

1. 检查游戏未运行
2. 若 `<游戏目录>\Mods` 已是 junction → 删除链接（**注意**：删 junction 不能递归删内容，必须先判断 `ReparsePoint` 属性）
3. 若 `<游戏目录>\Mods` 是普通目录且非空 → **不静默删除**，提示用户先迁移或备份（首次使用时提供"接管现有 Mods 目录"的选项：把现有内容移动到实例 Mod 库）
4. 建立 `mklink /J "<游戏目录>\Mods" "<实例>\Mods"`
5. 校验链接建立成功

**模式 B（重定向）启用某实例**：

1. 清空 `<实例>\Selected Mods`（删的是 junction，不伤实体文件）
2. 对启用清单中每个 Mod，在 `Selected Mods` 下建 junction 指向实体目录
3. uniqueId 去重；链接名冲突时加后缀区分
4. 启动时设 `SMAPI_MODS_PATH` 环境变量

> ⚠️ **删除 junction 的陷阱**：`Directory.Delete(path, true)` 对 junction 只删链接本身，但对符号链接在某些 .NET 版本上会递归删源目录。实现时必须先检查 `FileAttributes.ReparsePoint`，用非递归删除。

### 7.4 存档隔离（可选项，默认关）

开启时：`%appdata%\StardewValley\Saves` → junction → `<实例>\Saves`

**必须提示的风险**：
- Steam 云存档会与本机制冲突（会反复重命名存档文件），**需先关闭星露谷的 Steam 云同步**
- 该路径是全局的，同一时刻只能挂一个实例
- 切换前必须确认游戏已退出
- 首次启用时把现有存档**复制**（而非移动）到实例目录，保证安全

### 7.5 启动游戏与日志

**进程启动**：

```
FileName        = <游戏目录>\StardewModdingAPI.exe
WorkingDirectory= <游戏目录>
UseShellExecute = false
CreateNoWindow  = false            // 保留 SMAPI 控制台窗口
RedirectStandardOutput/Error = true
StandardOutputEncoding = Encoding.UTF8   // ← Stardrop 与 PCL 都漏了，中文必然乱码
```

- 捕获 stdout/stderr 用三段式：回调只入缓冲 → 定时器批量取出 → UI 线程刷新
- 堆栈续行（以 `   at ` / `Caused by: ` / `   ... ` 开头）继承上一行的日志等级
- 同时读 `%appdata%\StardewValley\ErrorLogs\SMAPI-latest.txt` 拿 SMAPI 与游戏版本号（正则 `SMAPI (?<smapiVersion>.+) with Stardew Valley (?<gameVersion>.+) on (?<system>.+)`）
- 用进程存活轮询（500ms）判定退出；退出码非 0 且曾正常运行 → 判定疑似崩溃

### 7.6 依赖检查与排序

1. 建立 `UniqueID → ModEntry` 索引（注意：同一 uniqueId 可能有多个副本，需按规则择一）
2. 对每个 Mod 的 `Dependencies`（`IsRequired != false`）与 `ContentPackFor` 求值：
   - 找不到 → 缺失依赖
   - 找到但版本 < `MinimumVersion` → 版本不符
3. 构建依赖图，做拓扑排序；检测到环 → 标记为循环依赖并报警
4. 排序结果写入 SMAPI 加载顺序配置（第 2 节决策三）
5. 依赖关系只做**报警与建议**，不做自动启用/禁用（避免与用户意图冲突）
